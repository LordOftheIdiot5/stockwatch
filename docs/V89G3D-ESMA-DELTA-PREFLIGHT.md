# V89g.3d — FIRDS daily revision preflight
ESMA official instructions, section 4.2, pages 12–13: https://www.esma.europa.eu/sites/default/files/library/esma65-8-5014_firds_-_instructions_for_download_of_full_and_delta_reference_files.pdf
Functional specification section 3.6.4: https://www.esma.europa.eu/sites/default/files/library/esma65-8-9568_-_firds_reference_data_functional_specifications_v2.10.pdf
The current weekly subset retains source-date evidence, not the exact publication-validity period. Before full replay, extend full-file extraction with TechAttrbts/PblctnPrd/FrDt, retain trading validity dates separately, and use ESMA's action-specific update rules. The four delta actions differ: new, modified, terminated, cancelled. Late terminations can introduce a previously unseen record; a same-start-date termination replaces the latest version, whereas a correction with a later valid-from date closes the previous validity period. Preserve raw evidence references and revision provenance even if the derived current-state view replaces a record. Do not apply all actions as deletion events. The full cancellation set is a consolidated reconciliation source, not another day's delta.
This PR checks that each day after the weekly baseline has a complete delta manifest through the last discovered delta date, downloads every part of only the latest discovered day, checks XML report/action schema and publishes aggregate counts/field paths in CI logs. No record values, historical replay or new identities published. A complete manifest is not proof of a complete replay; validate actual publication validity, late-reported rows, cancellation schema and a second independent weekly baseline before promoting current-state records.
