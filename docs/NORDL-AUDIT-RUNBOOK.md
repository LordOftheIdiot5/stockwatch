# Nordl audit runbook
2026-11-24 | N02/N19 permanent cross-platform quality gate
## Scope and cadence
All public routes of stocks.nordl.dev, energy.nordl.dev, leivro.com and nordl.dev, not merely homepages. Maintain an inventory from actual navigation, sitemaps and build manifests; include parameterized company/product pages, maps, charts, calculators, data/API and error routes, supported languages and themes.
- Each change: syntax, focused unit and browser regression, source/rights and data contract checks. No production mutation in tests.
- Each feature milestone: affected routes plus adjacent navigation and representative desktop 1440, tablet 1024, mobile 390 and narrow 320 CSS px, light/dark where supported. Keyboard, 200% zoom, normal/slow/failed/partial data, charts/maps and fallback.
- Before major release or every five substantial local versions: full route audit, review screenshots manually against approved references; accessibility, usefulness, performance, SEO, security and archive checks. After merge/deployment: live smoke, artifact/commit parity where supported, real source dates and key interactions. Weekly lightweight health/source/links check when operating automation is configured; monthly deeper UX/source/coverage review. No claim a new schedule is active until configured and verified.
## Fast tool selection
1. GitHub API/Actions: identify branch, SHA, workflow conclusion and actual job steps; do not rerun unchanged expensive suites if valid evidence exists. Inspect changed paths and use targeted tests first.
2. Local/CI syntax: node --check FILE; python -m py_compile FILE; node --test relevant_test.mjs; python -m unittest discover -s tests -v (from correct project directory). Use existing lockfiles and dependencies.
3. Playwright Chromium: real rendered browser, console/page errors, failed HTTP requests (distinguish expected third-party denials), screenshots, navigation, layout dimensions, keyboard and outage injection. Reuse a browser process and bounded concurrency; no destructive live interactions. Read actual pixels/screenshots before visual claims. TinyFish or public HTTP retrieval can help with read-only inspection but is not a replacement for real browser rendering, screenshot evidence or performance measurements.
4. Lighthouse CLI and axe-core (optional tools, install/pin after review): representative routes, repeat same device/network settings, report medians and actual accessibility violations. Lab metrics not real-user metrics; field Core Web Vitals from Search Console/CrUX when available. Check LCP, INP (field), CLS, payload and long tasks. No invented scores.
5. HTML parser/link checker, sitemap/robots/canonical/hreflang and structured-data checks; bounded same-origin crawl, no login or paid API calls. Search Console and Bing actual reports for indexing; do not infer indexing from HTTP 200.
6. Existing source validators, SQL integrity/foreign-key checks, R2 checksums and restore in separate private namespace; verify actual writes and receipts without publishing restricted records. Dependency audit (npm audit, pip-audit when installed), secret scanning, least privilege, auth/abuse/expiry and export rights. Do not log secrets or trigger production failures.

## Usefulness and visual review
For every key route identify target user, primary question, first-screen answer, evidence/date, primary action, successful task and missing data behavior. Can a visitor understand why a signal matters? Can they find a company/product/zone in a few actions, return without losing navigation and compare or export where permitted? Review hierarchy, density, whitespace, responsive overflow, legibility, theme consistency and screenshots against approved reference. Score only when rubric and evidence exist; no invented percentages. Recommend removal of redundant UI only after verifying functionality remains accessible. Prioritize substantive user problems over decorative redesign.
## Severity and acceptance
P0: data corruption/exposure, outage, broken core task, fabricated/stale-as-live claims; block release. P1: major responsive/functional/accessibility/data regression; fix before affected release or explicit documented exception. P2: polish, nonblocking optimization and research gaps; backlog with owner/next action. Every report: timestamp UTC, environment/branch/SHA, routes/devices, commands/workflow links, actual pass/fail/not-run, screenshot links, evidence, severity, remediation, retest and production verification. Never equate merge with deployment, static HTML with rendered page or a synthetic sample with real data.
